Cart basics

A game (a cart) is one JSON object. There is no code: entities are built from components, logic is written as rules, and values can be formulas. Names link things together — a prefab uses a sprite by name, a scene places prefabs by name, a rule changes scene by name.

{
  "format": "DCART-1",
  "meta":    { … },   title, screen size, first scene
  "vars":    { … },   global variables
  "sprites": { … },   pixel art or image files
  "sounds":  { … },   "music": { … },
  "tiles":   { … },   one-character map pieces
  "prefabs": { … },   entity templates made of components
  "scenes":  { … },   levels, menus, rooms
  "hud":     [ … ],   on-screen text, hearts, bars
  "rules":   [ … ]    game-wide logic
}
JSON rules: straight double quotes, no comments, no trailing commas. The Code tab’s Clean up fixes most mistakes, and Check lists anything that doesn’t link up.

Colours & palette

Anywhere a colour is expected you can use a palette number (0–31) or a "#rrggbb" string. In sprite pixel rows each colour has one character, shown bottom-left of each swatch; . is transparent. A cart can replace the palette with "palette": ["#000000", …].

sprites

"sprites": {
  "hero": { "w": 8, "h": 8, "scale": 2, "frames": [
    ["..rrrr..", ".rrrrrr.", "..7707..", "..7777..", ".hhhhhh.", "7.hhhh.7", "..h..h..", ".44..44."],
    ["..rrrr..", ".rrrrrr.", "..7707..", "..7777..", ".hhhhhh.", "7.hhhh.7", ".h....h.", "44....44"]
  ]},
  "boss": { "src": "boss.png", "w": 32, "h": 32 }
}
KeyWhat it does
w / hFrame size in pixels.
framesList of frames; each frame is h strings of w palette characters. Draw side views facing right — they flip automatically.
scaleDraw bigger in game (8×8 art at scale 2 fills a 16px tile).
srcLoad an image from the assets folder instead; it’s cut into w×h frames left→right, top→bottom.
stacktrue makes this a sprite stack — each frame becomes several pixel-art layers drawn with a small vertical offset for a chunky 3D look.

Sprite stacking

Draw a "totem" of flat pixel-art slices, offset upward by a few pixels each, to fake a solid 3D/voxel object — the technique behind games like Zaxxon and many top-down voxel racers. No 3D modelling, just more pixel art.

"rock": { "stack": true, "w": 8, "h": 8, "frames": [
  [ ["........","..nnnn..","..nnnn..","..nnnn..","..nnnn..","..nnnn..","........","........"],
    ["........","...nn...","...nn...","...nn...","...nn...","...nn...","........","........"],
    ["........","...ll...","...ll...","........","........","........","........","........"] ]
]}

Each element of frames is now a STACK: a list of layers, bottom to top, each an ordinary h-row pixel-art layer. A plain (non-stack) sprite has one nesting level less — frames: [ frame, frame, … ] where a frame is rows; a stack sprite has one level more — frames: [ stack, stack, … ] where a stack is [ layer, layer, … ] and a layer is rows.

For a rotating object (a kart, a boulder that can be viewed from any side), give it several stacks and pair it with "angles" (see Mode 7) — each angle is simply a separately pre-drawn stack, so nothing has to be sheared or faked at runtime; this is also how sprite-stacked vehicles work in Mode 7 racers. A single stack with no angles works anywhere (top-down, platformer) as a static chunky object — trees, pillars, crates, rocks. Stack sprites can't be hand-edited in the Sprites tab yet; build them in the Code tab or with the AI generator.

prefabs & components

A prefab is an entity template. Any component can go on any entity; mix freely. Every prefab is automatically tagged with its own name.

"slime": {
  "tags": ["enemy"],
  "sprite": { "name": "slime", "fps": 4, "anim": { "idle": [0,1], "die": [2,3,3] } },
  "body": { "w": 12, "h": 9 },
  "ai": { "type": "chase", "speed": 26, "range": 70, "idle": "wander" },
  "health": { "hp": 2, "effect": "poof", "drop": [ {"prefab":"coin","count":[1,2]} ] },
  "hurt": { "damage": 1, "targets": ["player"] }
}

Behaviors & inheritance

Two ways to reuse a set of components and rules across many prefabs, instead of copy-pasting them.

extends

"extends":"baseName" starts a prefab as a full copy of another prefab, then lays this prefab's own fields on top. The child's fields win on a clash; rules and tags are combined rather than replaced, so a child keeps everything the parent gave it and can still add its own.

"enemy_base": { "body": {"w":12,"h":12}, "health": {"hp":3}, "hurt": {"damage":1,"targets":["player"]} },
"goblin": { "extends": "enemy_base", "sprite": {"name":"goblin"}, "ai": {"type":"patrol","speed":30} }

behaviors & use

"behaviors" is a cart-level dict of reusable, parametrized bundles of components and rules. A prefab lists the ones it wants in "use", optionally overriding some of that behavior's parameters.

"behaviors": {
  "patrols": { "params": {"moveSpeed":30}, "tags": ["enemy"], "ai": {"type":"patrol","speed":"=self.moveSpeed"} },
  "shootsAt": { "params": {"rate":2,"bullet":"arrow"}, "use": ["patrols"],
                "attack": {"auto":true,"prefab":"=self.bullet","cooldown":"=self.rate"} }
},
"prefabs": {
  "goblin":   { "sprite": {"name":"goblin"}, "health": {"hp":3}, "use": ["patrols"] },
  "archer":   { "sprite": {"name":"archer"}, "health": {"hp":2}, "use": [ {"shootsAt": {"rate":0.6}} ] }
}

Param names must avoid the entity's built-in fields (see the reserved-names note under Formulas) — that's why this uses moveSpeed, not speed: self.speed is already reserved for the entity's current movement speed, so a param called speed would be silently shadowed and never read.

A behavior's params are its defaults; "use":[{"shootsAt":{"rate":0.6}}] overrides just rate for that prefab. Params become entity vars, so both the behavior's own fields ("=self.rate") and the prefab's own rules can read them as self.rate — the same formula mechanism as everywhere else (see Formulas). A behavior can itself use other behaviors. Precedence, most specific wins: a prefab's own fields > behaviors it uses (later ones override earlier ones) > what it extends — except rules/tags, which always combine across every layer.

States

A states component turns a prefab into a state machine — boss phases, enemy modes, doors, day/night — instead of a pile of when rules with hand-rolled flags.

"states": {
  "start": "asleep",
  "asleep":  { "ai": {"type":"turret"},
               "rules": [ {"on":"when","if":"dist(self,player) < 80", "goto":"awake"} ] },
  "awake":   { "enter": [ {"sound":"roar"}, {"text":"It wakes up!","t":1} ], "ai": {"type":"chase","speed":40},
               "rules": [ {"on":"hit", "if":"self.hp <= self.maxhp / 2", "goto":"enraged"} ] },
  "enraged": { "enter": [ {"shake":0.4}, {"comp":"ai.speed","value":90} ], "ai": {"type":"chase","speed":90},
               "rules": [ {"on":"die", "do": [ {"cancelDeath":true}, {"goto":"dead"} ] } ] },
  "dead":    { "enter": [ {"text":"Defeated!","t":2}, {"add":"gold","value":50} ], "ai": {"type":"turret"} }
}
KeyWhat it does
startThe first state's name (or the first key, if omitted).
a state's own fieldsAny component (sprite, ai, control, body, attack…) it lists overrides the prefab's normal value while that state is active; anything it doesn't mention is unchanged. health cannot be overridden per state.
enter / exitActions that run once, exactly when the state is entered / left.
rulesRules that only run in this state — the same events as ordinary entity rules (when, every, hit, touch, tile, button, die…).

{"goto":"name"} is an action that switches state — it runs the old state's exit, applies the new state, then runs its enter. As a shortcut, "goto" can sit directly on a rule alongside its own if, instead of inside do.

self.mode reads the current state's name in a formula or in {braces} text, e.g. "HP: {self.hp} ({self.mode})".

Surviving death: cancelDeath

Health reaching 0 removes the entity immediately — unless a rule for the die event calls {"cancelDeath":true} first. That's how a boss survives to a "dead" state instead of vanishing, as in the enraged state above. Use an "on":"die" rule for this, not a per-frame when check on self.hp — a per-frame check runs too late, after the entity is already gone.

Branches

if / else inside a conversation

A say while a conversation is open adds its lines to that conversation — in order, with the same speaker — so several if/else checks can each add a line.

"talk": { "name": "Guard", "lines": ["Halt!"], "then": [
  { "if": "keys > 0",   "then": [ {"say": ["You have a key."]} ],     "else": [ {"say": ["No key, no entry."]} ] },
  { "if": "gold >= 10", "then": [ {"say": ["And you look rich."]} ],  "else": [ {"say": ["And you look poor."]} ] },
  { "say": [ { "text": "Pay a 3 gold toll?", "choices": [
    { "text": "Pay", "do": [ { "if": "gold >= 3", "then": [ {"add":"gold","value":-3}, {"say":["Thank you."]} ],
                                                  "else": [ {"say":["You cannot afford it!"]} ] } ] },
    { "text": "Refuse", "cancel": true } ] } ] }
] }

Branches

The first branch whose if is true replaces the NPC’s lines; its do runs when that conversation ends (instead of then). A branch without if always matches. self.talks counts finished conversations with this NPC, so "self.talks == 0" means a first meeting.

"farmer": { "sprite": { "name": "farmer" }, "solid": true, "talk": {
  "name": "Farmer",
  "branches": [
    { "if": "flags.questDone", "lines": ["Thanks again, hero!"] },
    { "if": "inv.turnips >= 10", "lines": ["Ten turnips! Here's your reward."],
      "do": [ {"add":"inv.turnips","value":-10}, {"set":"flags.questDone","value":true}, {"add":"gold","value":100} ] },
    { "if": "self.talks > 0", "lines": ["Back again? Bring me 10 turnips.", "You have {inv.turnips} so far."] }
  ],
  "lines": [
    "Welcome to the farm!",
    { "text": "Oh, a lamp! Handy in the well.", "if": "has(inv.items,'lamp')" },
    { "text": "Moo.", "name": "Cow" },
    { "text": "Buy seeds for 20 gold?", "choices": [
      { "text": "Yes please", "if": "gold >= 20", "do": [ {"add":"gold","value":-20}, {"add":"inv.seeds","value":5} ], "lines": ["Here are 5 seeds."] },
      { "text": "I can't afford it", "if": "gold < 20", "lines": ["Come back later."] },
      { "text": "No thanks", "cancel": true, "lines": ["Suit yourself."] } ] }
  ]
}}

Doors & arrivals

Changing scene without at/tx places players on the doorway in the new scene that leads back to where they came from (a tile rule, warp, or collide rule pointing back). Otherwise they appear at their legend spawn. A doorway you arrive on won’t fire until you step off it. Use "at":"D" to choose a specific character or tag.

Variables

Global vars persist across scenes and can hold numbers, text, lists and nested objects. Reach inside with dots. Each entity also has its own vars (self.stage).

"vars": { "gold": 0, "day": 1, "inv": { "seeds": 3, "items": [] }, "flags": { "metElder": false } }

{"add":"inv.seeds","value":-1} · {"push":"inv.items","value":"lamp"} · {"set":"flags.metElder","value":true} · {"reset":true} restores the starting values.

Formulas

A string starting with = is calculated. Conditions can be plain formula text. Text anywhere can embed formulas in braces: "Day {day} — {inv.seeds} seeds". A whole text field can also just be one bare formula, e.g. "text": "='Day ' + str(day)" — either style works everywhere text does; {braces} tends to read cleaner for a few values dropped into a sentence, a bare formula for a fully computed line. Formulas only read game values; nothing else can run.

{ "add": "gold", "value": "=price * qty" }
{ "if": "gold >= 50 and not flags.boughtSword", "then": [ … ] }
{ "velocity": "self", "vy": "=-200 - self.power * 20" }
PartDetails

namesGlobal vars by name; self, other, player, a, b; time, frame, scene, tilt.x, tilt.y, screen.w/h, cam.x/y, map.w/h. In break/hit rules: tx, ty, tile, amount.

Reserved: x y vx vy cx cy w h tx ty hp maxhp onGround dir diry age id alive prefab player sprite mode z heading speed wp are always self's built-in fields, never a var — a var or behavior param with one of these exact names is shadowed and silently reads the built-in instead. Needed a speed number? Call it moveSpeed, not speed.

if / else on a rule

Any rule except when can check a condition itself: do runs if it’s true, else if not.

{ "on": "tile", "tile": "F", "tag": "player", "if": "cp == 1",
  "do":   [ { "set": "cp", "value": 0 }, { "add": "lap" } ],
  "else": [ { "text": "Go through the checkpoint first!", "t": 1.5 } ] }

Conditions

A formula string, or {"var":"keys","op":">=","value":1}, {"count":"enemy","op":"==","value":0}, {"all":[…]}, {"any":[…]}, {"not":…}, {"chance":0.5}.

Loot tables

Used by health.drop, tile break.drop / hit.drop and the drop action. Several items scatter; items with a body pop out.

FormMeaning
"coin"Always one coin.
["coin","coin","heart"]All of these.
[{"prefab":"heart","chance":0.3}, …]Each entry rolled on its own; chance (formula ok), count (number or [min,max]), if.
{"one":[{"prefab":"heart","weight":1}, …]}Exactly one, picked by weight. "prefab": null means nothing.

  { "prefab": "coin", "count": [1, 3] },
  { "prefab": "key", "if": "not flags.gotKey" },
  { "one": [ { "prefab": "heart", "weight": 1 }, { "prefab": "bomb_item", "weight": 1 }, { "prefab": null, "weight": 3 } ] }
]

Effects & death animations

One-shot effects — "effect": "leaf_burst" on tile breaks, bumps, deaths (health.effect), hits (health.hitEffect) or the effect action. Use a sprite name (its frames play once at 12 fps, in front of everything) or a prefab name (spawned there, so it can carry its own sound, particles, rules and lifetime).

Death animations — give the sprite an "anim": {"die": [4,5,6]}. When it dies it stops, plays those frames, then drops its loot and disappears. health.dieTime sets the length yourself.

"sprites": { "leaf_burst": { "w": 16, "h": 16, "frames": [ [ … ], [ … ], [ … ], [ … ] ] } },
"tiles":   { "b": { "sprite": "bush", "solid": true, "break": { "effect": "leaf_burst" } } },
"prefabs": { "pot_smash": { "sprite": { "name": "pot_shards", "fps": 10, "loop": false },
                            "lifetime": { "t": 0.4 }, "noCollide": true, "layer": 1,
                            "rules": [ { "on": "spawn", "do": [ { "sound": "crash" }, { "shake": 0.1 } ] } ] } }

Singletons & saving

Singletons in meta.singletons exist once for the whole game and keep running in every scene — perfect for day/night clocks, quest trackers and weather.

"meta": { "singletons": ["clock"], "persist": ["day", "gold", "inv"] },
"prefabs": { "clock": { "rules": [ { "on": "every", "t": 60, "do": [ { "add": "day" }, { "emit": "newDay" } ] } ] } }

Save memory works like a SNES battery: {"save":true} stores the variables listed in meta.persist, {"load":true} brings them back, {"erase":true} clears them, and hasSave() shows a Continue option.

Controls, feel & multiplayer

InputTouch / keyboard / gamepad
up down left rightD-pad · arrows or WASD · stick / d-pad
aA · Z, J or Space · bottom face button
bB · X or K
x / yX, Y · C/U, V/I
start / selectStart, Select · Enter, Shift

Haptics buzz automatically when the player is hurt, dies, stomps, picks up or breaks something; add your own with {"haptic":…}. Motion: with meta.motion, formulas read tilt.x/tilt.y (−1…1) and rules can use {"on":"shake"}; karts steer with tilt. Players adjust both under Controls.

Multiplayer: up to 4 players over a direct peer-to-peer link. Extra players copy player 1’s prefab (or meta.coop), are tagged player and p2–p4, and their health var gets the number appended (hp2).

Locked door that needs a key

"L": { "sprite": "locked_door", "solid": true, "tags": ["lock"],
       "rules": [ { "on": "touch", "tag": "player", "do": [
         { "if": "keys > 0", "then": [ { "add": "keys", "value": -1 }, { "sound": "unlock" }, { "effect": "dust", "at": "self" }, { "destroy": "self" } ],
           "else": [ { "say": ["It's locked."] } ] } ] } ] }

Shop counter with a menu

"shopkeep": { "sprite": { "name": "merchant" }, "solid": true, "talk": { "name": "Merchant", "lines": [
  { "text": "What'll it be? You have {gold} gold.", "choices": [
    { "text": "Lamp (50)", "if": "not has(inv.items,'lamp')",
      "do": [ { "if": "gold >= 50", "then": [ {"add":"gold","value":-50}, {"push":"inv.items","value":"lamp"}, {"say":["A fine choice!"]} ],
                "else": [ {"say":["You need more gold."]} ] } ] },
    { "text": "Potion (10)", "if": "gold >= 10", "do": [ {"add":"gold","value":-10}, {"add":"inv.potions"} ], "lines": ["Stay safe out there."] },
    { "text": "Just looking", "cancel": true, "lines": ["Come again!"] } ] } ] } }

"crop": { "tags": ["crop"], "sprite": { "name": "sprout" }, "vars": { "stage": 0 },

  ] }

Boss with a second phase

"rules": [ { "on": "when", "if": "self.hp <= self.maxhp / 2", "do": [
  { "text": "The golem is furious!", "t": 1.5 }, { "shake": 0.5 },
  { "comp": "ai.speed", "value": 70 }, { "comp": "attack.cooldown", "value": 0.6 }, { "setSprite": "golem_angry" } ] } ]

A one-off speed-up like this is fine with a plain rule. For a boss with several real phases — different attacks, a defeated state it survives into — use states instead, below.

Boss that survives to a defeated state

"states": {
  "start": "phase1",
  "phase1": { "ai": {"type":"chase","speed":40},
              "rules": [ {"on":"hit","if":"self.hp <= self.maxhp / 2","goto":"phase2"} ] },
  "phase2": { "enter": [ {"shake":0.4}, {"setSprite":"golem_angry"} ], "ai": {"type":"chase","speed":80},
              "attack": {"auto":true,"prefab":"boulder","cooldown":0.6},
              "rules": [ {"on":"die","do":[ {"cancelDeath":true}, {"goto":"defeated"} ]} ] },
  "defeated": { "enter": [ {"text":"The golem crumbles!","t":2}, {"add":"gold","value":100} ], "ai": {"type":"turret"} }
}
